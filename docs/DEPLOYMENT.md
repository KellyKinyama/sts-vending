# STS Vending — Production Deployment

This guide covers running STS Vending and the `nectar_sts_dart` token
engine as long-lived services on a single host or container set. It
deliberately focuses on **production** — for first-machine dev setup
see [QUICKSTART.md](QUICKSTART.md); for the full configuration
reference and test matrix see
[DEPLOYMENT_AND_TESTING.md](DEPLOYMENT_AND_TESTING.md).

## 1. Topology & sizing

The minimal production topology is **single-host, three processes,
one database**:

```
                ┌────────────────────────────┐
                │  nginx (TLS termination)   │
                │  :443 → app, :8787 internal│
                └─────────────┬──────────────┘
                              │
        ┌─────────────────────┼─────────────────────┐
        ▼                     ▼                     ▼
  php-fpm / artisan      queue worker        Dart engine
   (Laravel app)        (sts-queue)        (nectar-sts)
        │                     │                     │
        └─────────────────────┼─────────────────────┘
                              ▼
                       MySQL 8/9 (sts_vending)
```

Recommended baseline for ≤500 tokens/minute:

| Component   | CPU       | RAM       | Disk          |
| ----------- | --------- | --------- | ------------- |
| App + Dart  | 2 vCPU    | 2 GB      | 20 GB SSD     |
| MySQL       | 2 vCPU    | 4 GB      | 50 GB SSD     |

Scale horizontally by adding stateless app+Dart nodes behind a load
balancer; MySQL stays single-writer (use a managed RDS-style
replica for read scale-out if dashboards become heavy).

> **Important** — Laravel's `TokenController` and a DB-backed Dart
> engine **must not both write `tokens`** for the same issuance, or
> you get duplicate rows. Pick one writer per deployment. The
> default deployment routes all issuance through Laravel and runs
> Dart in JSON-file mode for its own audit log. See
> [DEPLOYMENT_AND_TESTING.md §5.1](DEPLOYMENT_AND_TESTING.md).

## 2. Pre-flight checklist

Run through this list **before** touching the production host. Every
item must be a "yes".

- [ ] Production vending key (`VENDING_KEY_HEX`) has been
      generated by KMS / HSM and is stored in a vault — not in
      `.env`, not in source control, not on chat.
- [ ] Production bearer token (`STS_ENGINE_TOKEN` /
      `NECTAR_API_TOKEN`) is at least 32 random bytes
      (`openssl rand -hex 32`) and stored in the same vault.
- [ ] MySQL DBA has created a least-privilege user for the app
      (`GRANT SELECT, INSERT, UPDATE, DELETE, EXECUTE ON
      sts_vending.* TO 'sts_app'@'%'`) and a separate read-only
      user for the engine if it runs in DB-backed mode.
- [ ] DNS A/AAAA records point at the load balancer / host.
- [ ] TLS certificate (Let's Encrypt or commercial) is renewable.
- [ ] Time sync is enabled (`w32time` on Windows, `chrony` or
      `systemd-timesyncd` on Linux). STS token TID validation is
      minute-precise; a 30-second skew between issuer and meter is
      tolerable, more is not.
- [ ] Backup plan for `sts_vending` schema is scheduled
      (see [§9](#9-backup-restore-rollback)).
- [ ] Off-host log shipping is configured (CloudWatch, ELK,
      Datadog, Loki — pick one).
- [ ] Smoke check passes locally against a staging host:
      `php artisan sts:smoke --amount=1.0`.

## 3. Windows Server deployment (NSSM)

Target: Windows Server 2019/2022, IIS optional (use nginx for
reverse proxy in [§6](#6-reverse-proxy--tls)).

### 3.1 Lay down the application

```powershell
# As Administrator
mkdir C:\apps; cd C:\apps
git clone https://example.invalid/sts-vending.git
cd sts-vending

# Install runtime deps (one-time per machine)
choco install php composer nodejs-lts mysql dart-sdk nssm -y

# Install app deps
composer install --no-dev --optimize-autoloader
npm ci
npm run build
```

Populate `C:\apps\sts-vending\.env` from your vault. Mandatory
values:

```dotenv
APP_NAME="STS Vending"
APP_ENV=production
APP_KEY=                       # filled by `php artisan key:generate`
APP_DEBUG=false
APP_URL=https://vending.example.com

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_DATABASE=sts_vending
DB_USERNAME=sts_app
DB_PASSWORD=<from vault>

STS_ENGINE_URL=http://127.0.0.1:8787
STS_ENGINE_TOKEN=<from vault>  # === NECTAR_API_TOKEN on Dart side
STS_ENGINE_TIMEOUT=10

LOG_CHANNEL=stack
LOG_LEVEL=warning
SESSION_DRIVER=database
QUEUE_CONNECTION=database
CACHE_STORE=database
```

Finalise:

```powershell
php artisan key:generate --force
php artisan migrate --force
php artisan config:cache
php artisan route:cache
php artisan view:cache
```

### 3.2 Install the Dart engine

```powershell
mkdir C:\apps\nectar_sts_dart; cd C:\apps\nectar_sts_dart
git clone https://example.invalid/nectar_sts_dart.git .
dart pub get
```

### 3.3 Register services with NSSM

```powershell
# Dart token engine
nssm install nectar-sts "C:\tools\dart-sdk\bin\dart.exe" `
    run bin/server.dart
nssm set nectar-sts AppDirectory     C:\apps\nectar_sts_dart
nssm set nectar-sts AppStdout        C:\logs\nectar-sts.out.log
nssm set nectar-sts AppStderr        C:\logs\nectar-sts.err.log
nssm set nectar-sts AppRotateFiles   1
nssm set nectar-sts AppRotateBytes   10485760
nssm set nectar-sts Start            SERVICE_AUTO_START
nssm set nectar-sts AppEnvironmentExtra `
    PORT=8787 `
    HOST=127.0.0.1 `
    VENDING_KEY_HEX=<from vault> `
    NECTAR_API_TOKEN=<from vault> `
    STS_DB_HOST= `
    VENDING_LOG_FILE=C:\apps\nectar_sts_dart\state\vending.json `
    METER_REGISTRY_FILE=C:\apps\nectar_sts_dart\state\meters.json

# Laravel built-in server (fine for ≤200 req/min; otherwise use
# nginx + php-fpm — see §4 for the recipe and §6 for the proxy)
nssm install sts-app "C:\tools\php\php.exe" `
    artisan serve --host=127.0.0.1 --port=8000
nssm set sts-app AppDirectory  C:\apps\sts-vending
nssm set sts-app AppStdout     C:\logs\sts-app.out.log
nssm set sts-app AppStderr     C:\logs\sts-app.err.log
nssm set sts-app Start         SERVICE_AUTO_START

# Queue worker
nssm install sts-queue "C:\tools\php\php.exe" `
    artisan queue:work --tries=3 --timeout=60
nssm set sts-queue AppDirectory  C:\apps\sts-vending
nssm set sts-queue AppStdout     C:\logs\sts-queue.out.log
nssm set sts-queue AppStderr     C:\logs\sts-queue.err.log

# Scheduler
nssm install sts-cron "C:\tools\php\php.exe" artisan schedule:work
nssm set sts-cron AppDirectory  C:\apps\sts-vending

# Start in dependency order
nssm start nectar-sts
nssm start sts-app
nssm start sts-queue
nssm start sts-cron
```

### 3.4 Verify

```powershell
Invoke-WebRequest http://127.0.0.1:8787/healthz | Select-Object StatusCode
cd C:\apps\sts-vending
php artisan sts:smoke
```

Both must return `200` / exit 0.

## 4. Linux deployment (systemd + nginx)

Target: Ubuntu 22.04 / 24.04 LTS or RHEL 9.

### 4.1 Install runtimes

```bash
sudo apt-get update
sudo apt-get install -y php8.3-cli php8.3-fpm php8.3-mysql \
    php8.3-mbstring php8.3-xml php8.3-curl php8.3-gd \
    composer mysql-server nginx
# Dart 3 from official repo
curl -fsSL https://dl-ssl.google.com/linux/linux_signing_key.pub | \
    sudo gpg --dearmor -o /usr/share/keyrings/dart.gpg
echo "deb [signed-by=/usr/share/keyrings/dart.gpg arch=amd64] \
    https://storage.googleapis.com/download.dartlang.org/linux/debian stable main" | \
    sudo tee /etc/apt/sources.list.d/dart_stable.list
sudo apt-get update && sudo apt-get install -y dart
```

### 4.2 Lay down code

```bash
sudo mkdir -p /srv/sts-vending /srv/nectar_sts_dart
sudo chown -R www-data:www-data /srv/sts-vending /srv/nectar_sts_dart

sudo -u www-data git clone https://example.invalid/sts-vending.git /srv/sts-vending
sudo -u www-data git clone https://example.invalid/nectar_sts_dart.git /srv/nectar_sts_dart

cd /srv/sts-vending
sudo -u www-data composer install --no-dev --optimize-autoloader
sudo -u www-data npm ci && sudo -u www-data npm run build

cd /srv/nectar_sts_dart
sudo -u www-data dart pub get
```

`/srv/sts-vending/.env` mirrors the Windows version above; path
separators only change.

```bash
cd /srv/sts-vending
sudo -u www-data php artisan key:generate --force
sudo -u www-data php artisan migrate --force
sudo -u www-data php artisan config:cache route:cache view:cache
```

### 4.3 systemd units

Create `/etc/systemd/system/nectar-sts.service`:

```ini
[Unit]
Description=Nectar STS Dart token engine
After=network.target mysql.service
Wants=network-online.target

[Service]
Type=simple
User=www-data
Group=www-data
WorkingDirectory=/srv/nectar_sts_dart
EnvironmentFile=/etc/nectar-sts.env
ExecStart=/usr/bin/dart run bin/server.dart
Restart=on-failure
RestartSec=5
StandardOutput=append:/var/log/nectar-sts/out.log
StandardError=append:/var/log/nectar-sts/err.log
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true
ReadWritePaths=/srv/nectar_sts_dart/state /var/log/nectar-sts

[Install]
WantedBy=multi-user.target
```

`/etc/nectar-sts.env` (chmod `0600`, owned by `root:www-data`):

```bash
PORT=8787
HOST=127.0.0.1
VENDING_KEY_HEX=<from vault>
NECTAR_API_TOKEN=<from vault>
VENDING_LOG_FILE=/srv/nectar_sts_dart/state/vending.json
METER_REGISTRY_FILE=/srv/nectar_sts_dart/state/meters.json
```

Create `/etc/systemd/system/sts-queue.service`:

```ini
[Unit]
Description=STS Vending queue worker
After=network.target mysql.service
PartOf=sts-vending.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/srv/sts-vending
ExecStart=/usr/bin/php artisan queue:work --tries=3 --timeout=60 --sleep=3
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Create `/etc/systemd/system/sts-cron.service`:

```ini
[Unit]
Description=STS Vending scheduler
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/srv/sts-vending
ExecStart=/usr/bin/php artisan schedule:work
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

Enable and start:

```bash
sudo mkdir -p /var/log/nectar-sts /srv/nectar_sts_dart/state
sudo chown -R www-data:www-data /var/log/nectar-sts /srv/nectar_sts_dart/state
sudo systemctl daemon-reload
sudo systemctl enable --now nectar-sts sts-queue sts-cron
sudo systemctl status nectar-sts sts-queue sts-cron
```

Laravel itself is served by **php-fpm** (already installed). Skip
to [§6](#6-reverse-proxy--tls) for the nginx vhost.

## 5. Docker / Compose deployment

A minimal `compose.yaml` that runs all three services. Place it
next to checked-out copies of both repos:

```yaml
services:
  mysql:
    image: mysql:8.4
    restart: unless-stopped
    environment:
      MYSQL_DATABASE: sts_vending
      MYSQL_RANDOM_ROOT_PASSWORD: "yes"
      MYSQL_USER: sts_app
      MYSQL_PASSWORD: ${DB_PASSWORD}
    volumes:
      - mysql-data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      retries: 5

  nectar-sts:
    image: dart:3.4
    working_dir: /app
    command: ["dart", "run", "bin/server.dart"]
    volumes:
      - ./nectar_sts_dart:/app
      - nectar-state:/app/state
    environment:
      PORT: "8787"
      HOST: "0.0.0.0"
      VENDING_KEY_HEX: ${VENDING_KEY_HEX}
      NECTAR_API_TOKEN: ${NECTAR_API_TOKEN}
      VENDING_LOG_FILE: /app/state/vending.json
      METER_REGISTRY_FILE: /app/state/meters.json
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://127.0.0.1:8787/healthz"]
      interval: 15s
      retries: 5
    depends_on:
      mysql:
        condition: service_healthy

  app:
    build:
      context: ./sts-vending
      dockerfile: Dockerfile
    restart: unless-stopped
    environment:
      APP_ENV: production
      APP_DEBUG: "false"
      APP_KEY: ${APP_KEY}
      APP_URL: https://vending.example.com
      DB_CONNECTION: mysql
      DB_HOST: mysql
      DB_DATABASE: sts_vending
      DB_USERNAME: sts_app
      DB_PASSWORD: ${DB_PASSWORD}
      STS_ENGINE_URL: http://nectar-sts:8787
      STS_ENGINE_TOKEN: ${NECTAR_API_TOKEN}
    depends_on:
      mysql:
        condition: service_healthy
      nectar-sts:
        condition: service_healthy
    ports:
      - "8000:8000"

volumes:
  mysql-data:
  nectar-state:
```

Place secrets in a sibling `.env` (gitignored). Bring up:

```bash
docker compose up -d
docker compose exec app php artisan migrate --force
docker compose exec app php artisan sts:smoke
```

A minimal `sts-vending/Dockerfile`:

```dockerfile
FROM php:8.3-fpm-alpine
RUN apk add --no-cache nginx supervisor nodejs npm \
        oniguruma-dev libzip-dev icu-dev libpng-dev \
    && docker-php-ext-install pdo_mysql mbstring zip intl gd opcache
WORKDIR /var/www/html
COPY . .
RUN curl -sS https://getcomposer.org/installer | php -- --install-dir=/usr/local/bin --filename=composer \
 && composer install --no-dev --optimize-autoloader \
 && npm ci && npm run build \
 && chown -R www-data:www-data storage bootstrap/cache
EXPOSE 8000
CMD ["php", "artisan", "serve", "--host=0.0.0.0", "--port=8000"]
```

For production-grade serving inside the container, swap the `CMD`
for php-fpm + nginx and add a supervisord config — keeping the
image stateless is more important than the exact PID 1 choice.

## 6. Reverse proxy + TLS

Terminate TLS at nginx; proxy plain HTTP into Laravel and **never**
expose `:8787` (the Dart engine) to the public internet — it
should only ever be reachable from the Laravel host(s).

`/etc/nginx/sites-available/vending.example.com`:

```nginx
server {
    listen 80;
    server_name vending.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name vending.example.com;

    ssl_certificate     /etc/letsencrypt/live/vending.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/vending.example.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    add_header Strict-Transport-Security "max-age=31536000" always;
    add_header X-Content-Type-Options nosniff;
    add_header X-Frame-Options SAMEORIGIN;
    add_header Referrer-Policy strict-origin-when-cross-origin;

    root /srv/sts-vending/public;
    index index.php;

    client_max_body_size 8M;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;
        fastcgi_index index.php;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        include fastcgi_params;
        fastcgi_read_timeout 30s;
    }

    location ~ /\.(?!well-known).* { deny all; }
}
```

Obtain a cert and reload:

```bash
sudo certbot --nginx -d vending.example.com
sudo ln -s /etc/nginx/sites-available/vending.example.com \
    /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

Firewall (`ufw` example):

```bash
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
# DO NOT open 8787 — Dart engine is loopback-only.
sudo ufw enable
```

## 7. Secrets management

Never commit these to git, never echo them in CI logs, never paste
in chat:

| Secret               | Lives in                                  |
| -------------------- | ----------------------------------------- |
| `APP_KEY`            | `.env` (rotated only via key:generate + re-encrypt of all `vending_keys.vudk_blob`) |
| `DB_PASSWORD`        | `.env` and `/etc/nectar-sts.env`          |
| `STS_ENGINE_TOKEN`   | `.env`                                    |
| `NECTAR_API_TOKEN`   | `/etc/nectar-sts.env` (== `STS_ENGINE_TOKEN`) |
| `VENDING_KEY_HEX`    | `/etc/nectar-sts.env` AND mirrored into `vending_keys.vudk_blob` (encrypted at rest by Laravel `Crypt`) |

Recommended vault paths: HashiCorp Vault `secret/sts-vending/<env>`,
AWS Secrets Manager `sts-vending/<env>/*`, Azure Key Vault. Inject
at process-start by templating the env file or using
`vault agent` / `aws ssm get-parameters`.

**Rotating `APP_KEY`** invalidates every encrypted `vudk_blob`.
Procedure:

1. `php artisan tinker` → dump every `VendingKey::all()->pluck(['id', 'vudk_blob_plain'])`
   using the helper accessor.
2. `php artisan key:generate --force`.
3. Re-encrypt each row by setting `vudk_blob` to its plaintext (the
   mutator re-encrypts).
4. Restart `sts-app` so the cached config picks up the new key.

**Rotating the vending key (`VENDING_KEY_HEX`)** rotates the
cryptographic root for every meter that uses it. Coordinate with
field deployment — meters keyed under the old VUDK will reject
tokens minted under the new one. Use a fresh `key_revision_number`
on the matching `vending_keys` row.

## 8. Database operations

### 8.1 Create the schema (production user)

```sql
CREATE DATABASE sts_vending CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'sts_app'@'%' IDENTIFIED BY '<vault password>';
GRANT SELECT, INSERT, UPDATE, DELETE, EXECUTE
    ON sts_vending.* TO 'sts_app'@'%';
CREATE USER 'sts_app_ddl'@'localhost' IDENTIFIED BY '<other password>';
GRANT ALL ON sts_vending.* TO 'sts_app_ddl'@'localhost';
FLUSH PRIVILEGES;
```

Run migrations as `sts_app_ddl` (set `DB_USERNAME` temporarily), then
switch the app `.env` back to `sts_app` for runtime.

### 8.2 MySQL 8/9 auth note

If the Dart engine runs in DB-backed mode against MySQL ≥8 with
`caching_sha2_password` (default), either:

- Set `STS_DB_SSLMODE=require` in `/etc/nectar-sts.env`, **or**
- Recreate its user with `IDENTIFIED WITH mysql_native_password`.

Without one of these the `mysql_dart` driver fails the handshake.

### 8.3 Migrations

```bash
cd /srv/sts-vending
sudo -u www-data php artisan migrate --force
```

Always run with `--force` in non-interactive environments and only
after confirming the migration list (`php artisan migrate:status`).

## 9. Backup, restore, rollback

### 9.1 Logical backup (nightly)

`/etc/cron.daily/sts-vending-backup`:

```bash
#!/bin/bash
set -euo pipefail
TS=$(date +%F-%H%M)
DEST=/srv/backups/sts-vending
mkdir -p "$DEST"
mysqldump --single-transaction --routines --triggers \
    --user=sts_app_ddl --password="$DB_DDL_PASSWORD" \
    sts_vending | gzip > "$DEST/db-$TS.sql.gz"
tar czf "$DEST/state-$TS.tgz" /srv/nectar_sts_dart/state /srv/sts-vending/storage
find "$DEST" -mtime +30 -delete
```

Mirror nightly to off-host storage (S3, BunnyCDN, rsync to a
remote host).

### 9.2 Restore

```bash
sudo systemctl stop sts-queue sts-cron sts-app nectar-sts
gunzip -c /srv/backups/sts-vending/db-2026-06-01-0200.sql.gz | \
    mysql -u sts_app_ddl -p sts_vending
tar xzf /srv/backups/sts-vending/state-2026-06-01-0200.tgz -C /
sudo systemctl start nectar-sts sts-app sts-queue sts-cron
cd /srv/sts-vending && php artisan sts:smoke
```

### 9.3 Application rollback

```bash
cd /srv/sts-vending
sudo -u www-data git fetch --tags
sudo -u www-data git checkout v1.2.3   # previous good tag
sudo -u www-data composer install --no-dev --optimize-autoloader
sudo -u www-data php artisan migrate:rollback --step=N --force  # if needed
sudo -u www-data php artisan config:cache route:cache view:cache
sudo systemctl restart sts-app sts-queue sts-cron
sudo -u www-data php artisan sts:smoke
```

Roll back the Dart engine the same way — `git checkout`, restart
the service. **Migrations that drop columns are irreversible** in
practice; treat them as forward-only and design with additive
migrations + multi-step deprecation.

## 10. Monitoring & health checks

### 10.1 Endpoints

| Endpoint                                | Source                                 | Use for |
| --------------------------------------- | -------------------------------------- | ------- |
| `GET http://127.0.0.1:8787/healthz`     | Dart engine                            | Liveness probe (returns `{"ok":true,"version":...}` on 200). |
| `GET https://vending.example.com/`      | Laravel dashboard                      | Readiness probe (200 means session DB + view cache are reachable). |
| `php artisan sts:smoke`                 | CLI                                    | Functional probe — exercises the full chain. Run via cron + alert on non-zero exit. |

### 10.2 Cron-based smoke alert

`/etc/cron.d/sts-vending-smoke`:

```cron
*/5 * * * * www-data cd /srv/sts-vending && /usr/bin/php artisan sts:smoke \
    >> /var/log/sts-smoke.log 2>&1 || \
    /usr/bin/curl -s -X POST -d "STS smoke failed at $(date)" \
        https://alerts.example.com/webhook
```

### 10.3 Log shipping

| File                            | What's in it |
| ------------------------------- | ------------ |
| `/srv/sts-vending/storage/logs/laravel.log` | Laravel app log (rotates daily via `LOG_CHANNEL=daily`). |
| `/var/log/nectar-sts/out.log`   | Dart engine stdout: per-request lines, key derivations, audit. |
| `/var/log/nectar-sts/err.log`   | Dart engine stderr: stack traces. |
| `/var/log/nginx/access.log`     | HTTP access. |
| `/var/log/mysql/error.log`      | DB errors. |

Ship all to your central log store; alert on:

- Any line matching `level=ERROR` or `level=CRITICAL` in the Laravel
  log.
- Any `Exception` line in `nectar-sts.err.log`.
- HTTP 5xx rate on the nginx access log > 1/minute over 5 minutes.
- `/healthz` non-200 for ≥ 60 seconds.

### 10.4 Database / metrics

Surface to your dashboard:

- Tokens issued per minute (`SELECT COUNT(*) FROM tokens WHERE
  issued_at > NOW() - INTERVAL 1 MINUTE GROUP BY status`).
- Failed-issuance ratio (`status='failed'` / total over 1h).
- MySQL `connections`, `queries`, `Innodb_buffer_pool_pages_dirty`.

## 11. Upgrade / zero-downtime deploy

Single-host upgrade procedure (≤30 s of dropped requests):

```bash
cd /srv/sts-vending
sudo -u www-data git fetch
sudo -u www-data git checkout v1.3.0
sudo -u www-data composer install --no-dev --optimize-autoloader
sudo -u www-data npm ci && sudo -u www-data npm run build

# Migrations FIRST (additive only; never destructive in a hot deploy)
sudo -u www-data php artisan down --retry=15
sudo -u www-data php artisan migrate --force
sudo -u www-data php artisan config:cache route:cache view:cache
sudo systemctl restart sts-app sts-queue
sudo -u www-data php artisan up

# Post-deploy smoke
sudo -u www-data php artisan sts:smoke || \
    (echo 'SMOKE FAILED — rolling back'; \
     sudo -u www-data git checkout - && sudo systemctl restart sts-app sts-queue; \
     exit 1)
```

For multi-host fleets, blue-green the app+Dart nodes behind your
load balancer:

1. Roll the new image onto the green fleet.
2. Run migrations from one green node only.
3. Wait for `/healthz` + smoke on green.
4. Cut traffic 10 % → 50 % → 100 % over 10 minutes.
5. Drain blue and decommission.

## 12. Hardening checklist

- [ ] `APP_DEBUG=false` and `APP_ENV=production` in `.env`.
- [ ] `php artisan route:cache`, `config:cache`, `view:cache` after
      every deploy.
- [ ] All Sanctum personal access tokens are scoped (`abilities`) —
      e.g. an issuance-only token cannot manage supply groups.
- [ ] OS firewall blocks inbound on `:8787` (Dart engine), `:3306`
      (MySQL) and `:8000` (raw artisan serve, if used).
- [ ] PHP `expose_php=Off`, `display_errors=Off`,
      `display_startup_errors=Off`.
- [ ] PHP `session.cookie_secure=1`, `session.cookie_httponly=1`,
      `session.cookie_samesite=Lax`.
- [ ] Logs do not include `vending_key` or `Authorization` headers
      (defaults already redact these — verify after any custom
      logging changes).
- [ ] `storage/` and `bootstrap/cache/` are writable only by the app
      user (`www-data`), not world-writable.
- [ ] Automated certificate renewal (`certbot renew --post-hook
      "systemctl reload nginx"`) is in `cron.d`.
- [ ] OS auto-update for security patches is enabled (`unattended-upgrades`
      on Ubuntu, `dnf-automatic` on RHEL, `Windows Update` set to
      install security updates).
